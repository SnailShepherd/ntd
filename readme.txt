NTD builder, версия 2026.02

БЫСТРЫЙ ЗАПУСК: двойной клик по NTD.bat
  Он делает всё сам:
    • берёт таблицы из data\tables
    • не берёт документы старше 6 месяцев (--doc-age-months 6)
    • имя отчёта подставляет по самой свежей таблице
    • показывает ход работы (--why): что качает и что отбросил
    • держит кэш в пределах 500 карточек, а data\done — 60 таблиц
  Чтобы поменять период, пределы или отключить очистку — откройте NTD.bat
  в блокноте, там всё подписано.

Две РАЗНЫЕ отсечки по дате — не путать:

1) --doc-age-months N — отсекает САМИ ДОКУМЕНТЫ по их возрасту.
   Точка отсчёта — дата отчёта, взятая из имени итогового файла:
     out\20260826.html  →  26.08.2026  →  порог 26.02.2026
   Скользит сама: имя файла берётся из свежей таблицы, значит и порог
   сдвигается с каждой выгрузкой, править руками ничего не нужно.
   Повторный прогон старой выгрузки даст тот же результат, что и в день
   выгрузки, — порог считается от отчёта, а не от «сегодня».
   Где известна полная дата утверждения, сравнение идёт по дате;
   у стандартов в обозначении есть только год (ГОСТ Р 72522-2026),
   поэтому там сравнение по году и в спорном году документ остаётся.
   В начале работы печатается:
     [OK] Дата отчёта: 2026-08-26; отбрасываю документы старше 6 мес.,
          т.е. до 2026-02-26

2) --from-date ГГГГ-ММ-ДД — отсекает ВХОДНЫЕ ТАБЛИЦЫ по дате в имени
   файла YYYYMMDD*.html. К содержимому таблиц отношения не имеет.
   Умолчание 2025-09-01. В NTD.bat не используется: в data\tables и так
   лежит только свежая выгрузка.

ПОЧЕМУ В NTD.bat НЕТ РУССКОГО ТЕКСТА В КОМАНДАХ echo
Python печатает в консоль Windows через Unicode, поэтому его русские
сообщения читаются всегда. А cmd выводит echo через кодовую страницу
консоли (у неё это cp850), и русские буквы превращаются в «крякозябры»
вида «â«Ô«ó«». Поэтому весь русский текст итога печатает скрипт, а в .bat
по-русски написаны только комментарии rem — на экран они не попадают.

Запуск (Windows / PowerShell / cmd):
  cd c:\normacs\ntd
  py -3 ntd.py --input-dir data/tables --from-date 2026-05-01 --why --out out/YYYYMMDD.html

По умолчанию:
  • from-date = 2025-09-01
  • years     = 2025,2026

После успешного завершения (если НЕ указан --dry и НЕ указан --no-move-done)
скрипт автоматически переносит обработанные *.html из input-dir в:
  • data/done  (по умолчанию для input-dir = data/tables)
или в папку, указанную через --done-dir

Полезные режимы:
  • Сухой прогон + причины отбора:
      py -3 ntd.py --input-dir data/tables --dry --why

  • Только 2026:
      py -3 ntd.py --input-dir data/tables --years 2026 --from-date 2026-01-01 --out out/ntd_2026.html

  • Отключить перенос в done:
      py -3 ntd.py --input-dir data/tables --no-move-done --out out/ntd.html

  • Отключить сортировку (оставить порядок входных таблиц):
      py -3 ntd.py --input-dir data/tables --no-sort --out out/ntd.html

Сортировка (по умолчанию включена):
Карточки из всех входных таблиц собираются вместе и сортируются по типу
документа в русском алфавитном порядке:
  ГОСТ (и все разновидности: ГОСТ EN, ГОСТ IEC, ГОСТ ISO, ГОСТ Р, ...) →
  ОСТ → Письмо → ПНСТ → Постановление → Приказ → Распоряжение → РД →
  Решение → СП → Федеральный закон
Внутри одного типа — по номеру «естественно» (9 перед 10, а не после 100),
затем по наименованию.

Имя итогового файла:
Если --out НЕ задан, имя берётся из самой свежей таблицы в input-dir:
  data/tables/20260826.html  →  out/20260826.html
«Самая свежая» определяется по дате в имени (YYYYMMDD), а не по алфавиту;
при совпадении дат берётся вариант с суффиксом (20260720_1 позже 20260720).
Папку можно сменить через --out-dir (по умолчанию out).

Очистка «хвостов» (в самом ntd.py ВЫКЛЮЧЕНА, включается любым из лимитов;
в NTD.bat уже включена: --keep-cache 500 --keep-done 60):
  --prune-days 30   удалить карточки в кэше и таблицы в done старше 30 дней
  --keep-cache 500  оставить в кэше только 500 самых свежих карточек
  --keep-done   60  оставить в done  только 60 самых свежих таблиц
Возраст таблиц в done считается по дате в имени файла, возраст карточек
в кэше — по времени изменения файла. Лимиты можно комбинировать.
С флагом --dry ничего не удаляется, только печатается, что было бы удалено:
  py -3 ntd.py --input-dir data/tables --dry --keep-cache 500 --keep-done 60
Удалённую из кэша карточку можно вернуть только повторной загрузкой
с сайта, а удалённые таблицы из done — из истории git.

Что видно во время работы:
  [12/51] качаю   28f9i — Приказ Росаккредитации...   (нет в кэше, идём на сайт)
  [13/51] из кэша 28lul — Письмо ФНС России...        (взято локально)
В конце — сводка: сколько карточек в отчёте, сколько взято из кэша,
сколько скачано, и сколько строк отброшено с разбивкой по причинам.

Входные таблицы — это *.html из --input-dir (НЕ csv).
Файлы classifiers.csv и classifiers_map.csv — это справочники классификаторов:
  • classifiers.csv     — белый список итоговых меток (одна колонка label)
  • classifiers_map.csv — правила: pattern,canonical_label,source
Оба файла в кодировке UTF-8 с BOM, чтобы Excel открывал их без «кракозябр».
Если в pattern или canonical_label есть запятая — всё поле нужно взять
в двойные кавычки, иначе колонки съедут:
  "^\s*13\b.*,.*",Название метки,alias
При несовпадении числа колонок скрипт печатает предупреждение [WARN].

Что НЕ попадает в git (см. .gitignore):
  • .temp/       кэш скачанных карточек
  • data/        входные таблицы и обработанные исходники
  • out/         готовые отчёты
  • __pycache__/ скомпилированные модули Python
В репозитории — только код и справочники классификаторов. Данные объёмные,
шумят в diff и хранятся в бэкапах, поэтому в git их нет.
Версии этих папок, попавшие в коммит v2026.01, при необходимости всё ещё
достаются из истории:
  git checkout db68e41 -- data/done/20260311.html
